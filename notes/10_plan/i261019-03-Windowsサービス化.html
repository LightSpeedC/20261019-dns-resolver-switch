導入・削除・置き替え

  1. 一般ユーザのコンソールから install-service.cmd を実行 → 自動で管理者へ昇格。自分のパスと winsw の複製元は、昇格の前に subst から実体のパスへ直して渡す
  2. 導入済みなら止めて削除する（入れ直し）
  3. node の複製: 使っている node の実体を deploy/node-dns-resolver-switch.exe へ写す。動いている exe は上書きできないので、止めてから写す
  4. winsw の複製（無ければ）、定義の存在を確かめる → install → start
  5. 5 秒待って状態・開始の種類・登録された実行ファイルのパスを表示する（subst のドライブになっていないことを目で確かめる）

ソースの更新は、サービスの再起動で反映される（node はソースを起動時に読む）。node の版を上げるときだけ、入れ直しで exe を写し直す。

確かめること

  • 導入後、nslookup example.com 127.0.0.1 と LAN の別の端末から引ける
  • サービスの停止で、ログに停止時の集計が出る（winsw の Ctrl+C が i261019-04 の停止処理に届く）
  • プロセスを強制終了すると 10 秒後に起動し直す
  • OS を再起動したあと、自動で起動している（共通ルール「自動実行に関わる変更は、実環境から動かして結果を見るまで済にしない」）。再起動は利用者が行う
winsw の再起動は終了コードを区別しない。0 以外ならすべて起動し直すので、i261019-04 で分けた「起動の失敗（2）」でも 10 秒ごとに起動し直し続ける。53 番を別のサービスが使っていると、ログに起動の失敗が 10 秒ごとに積もる。

決めてほしいこと

  1. 実行するアカウント
    • 5-A: LocalService（権限の小さい組み込みアカウント）。推す理由: DNS を外に開くので、乗っ取られたときの被害を小さくする。プロジェクトのフォルダを読めるかは導入時に確かめる
    • 5-B: winsw の既定（LocalSystem）。ai-chat-lite と同じで確実に動くが、権限が最も大きい
  2. LAN から届くようにする Windows ファイアウォールの許可
    • 6-A: 導入スクリプトが、この exe の 53 番（UDP・TCP）を「ローカル サブネット」からだけ許可する規則を足し、削除で消す。推す理由: 入れ忘れが無く、許す範囲も本体の許可リストと二重に絞れる
    • 6-B: 規則は足さず、手順だけ README に書く
  3. 管理者なしでの再起動（設定を変えたあとの反映）
    • 7-A: いまは作らない。再起動は管理者で Restart-Service。推す理由: 設定の変更は頻繁でない
    • 7-B: 受信箱のフォルダに依頼のファイルを置くと、自分で異常終了して起動し直す仕組みを足す（共通ルール「常駐サービスの置き場と、exe の置き替え」）
